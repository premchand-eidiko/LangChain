DAY 1 — SQL Basics 
1. Introduction to Databases and SQL 
What is data? Data is just raw facts — a name, a number, a date. On its own it doesn't tell you much. 
What is a database? A database is an organized place to store related data so it can be stored, searched, and 
updated easily — instead of scattering it across files. 
What is a DBMS? A Database Management System (DBMS) is the software that lets you create, read, update, 
and delete data in a database (e.g., Oracle, MySQL, SQL Server). 
What is an RDBMS? A Relational DBMS stores data in tables (rows and columns) and lets tables relate to each 
other using keys. Oracle, MySQL, and PostgreSQL are all RDBMS. 
What is SQL? SQL (Structured Query Language) is the language we use to talk to an RDBMS — to create tables, 
insert data, and ask questions ("queries") about that data. 
Why do we need SQL? Because almost every real-world application (banking, e-commerce, HR systems) stores 
its data in a relational database, and SQL is the standard way to interact with it. 
What is a table? A table is a structured grid of data — like a spreadsheet — with fixed columns and any number 
of rows. 
Row vs Column: A column defines what kind of data is stored (e.g., employee_name, salary) — fixed when the 
table is created. A row is one record — one employee, one order, one product.

Relational (SQL) Non-Relational (NoSQL)

DAY 2–3 — SQL Fundamentals 
4. SQL Data Types 
Type Used For 
INT Whole numbers (e.g., employee_id) 
BIGINT Very large whole numbers 
DECIMAL Exact decimal numbers (e.g., money) 
VARCHAR Variable-length text 
CHAR Fixed-length text 
TEXT Long text (paragraphs, descriptions) 
DATE Date only (2024-05-10) 
DATETIME Date + time 
TIMESTAMP Date + time, often auto-updated 
BOOLEAN True/False values 
 
CHAR vs VARCHAR: CHAR(10) always reserves 10 characters, padding with spaces. VARCHAR(10) only uses as 
much space as needed, up to 10 characters. Use VARCHAR for most text like names and emails. 
INT vs BIGINT: INT handles typical whole numbers. Use BIGINT only when numbers might exceed ~2.1 billion 
(rare for beginner projects). 
DECIMAL vs FLOAT: DECIMAL stores exact values — always use it for money (salary, price). FLOAT is 
approximate and can introduce rounding errors, so avoid it for financial data. 
Common Mistake: Using FLOAT for salary/price columns. Always use DECIMAL(10,2) for money. 
 
5. Creating and Selecting Databases 
CREATE DATABASE company_db; 
  
USE company_db; 
CREATE DATABASE makes a new, empty database. USE tells the server "all my next commands apply to this 
database." 
To remove a database entirely (deletes everything inside it): 
DROP DATABASE company_db; 
Common Mistake: DROP DATABASE is permanent — there's no undo. Never run it casually 
on a real project.

10. UPDATE 
UPDATE employees 
SET salary = 75000 
WHERE employee_id = 101; 
This changes Rahul's salary to 75000. 
Why WHERE matters: 
If you forget the WHERE clause: 
UPDATE employees 
SET salary = 75000; 
This updates every single row in the table — all employees get salary 75000! Always double-check your WHERE 
clause before running an UPDATE. 
Common Mistake: Running UPDATE without WHERE on a live table. Always SELECT with the same WHERE 
first to preview which rows will be affected.

This removes only Vikas's row. Just like UPDATE, forgetting WHERE here deletes all rows in the table.

DAY 4 — Querying Data 
12. SELECT 
SELECT * FROM employees; 
* means "all columns." Good for quick checks, but not ideal in real applications. 
SELECT employee_name, salary 
FROM employees; 
Why avoid SELECT *? It pulls unnecessary columns, wastes memory/network, and can break your application if 
the table structure changes later. Always select only the columns you actually need. 
 
13. DISTINCT 
SELECT DISTINCT department_id 
FROM employees; 
Returns each unique department_id only once, removing duplicates. 
 
14. WHERE 
SELECT * FROM employees 
WHERE department_id = 1; 
Filters rows so only matching ones are returned — here, only IT department employees.

16. AND / OR / NOT 
SELECT * FROM employees 
WHERE department_id = 1 AND salary > 70000; 
Both conditions must be true. 
SELECT * FROM employees 
WHERE department_id = 1 OR department_id = 4; 
Either condition can be true. 
SELECT * FROM employees 
WHERE NOT department_id = 1; 
Excludes IT department employees. 
 
17. BETWEEN 
SELECT * 
FROM employees 
WHERE salary BETWEEN 60000 AND 80000;

24. Aggregate Functions 
Function Purpose 
COUNT Number of rows 
SUM Total of a numeric column 
AVG Average value 
MIN Smallest value 
MAX Largest value 
 
SELECT COUNT(*) FROM employees;         -- total number of employees 
SELECT SUM(salary) FROM employees;      -- total salary paid 
SELECT AVG(salary) FROM employees;      -- average salary 
SELECT MIN(salary), MAX(salary) FROM employees; 
COUNT(*) vs COUNT(column): COUNT(*) counts all rows, including ones with NULL values. COUNT(email) 
counts only rows where email is not NULL. 
 
25. String Functions 
SELECT CONCAT(employee_name, ' - ', email) FROM employees;   -- joins text together 
SELECT LENGTH(employee_name) FROM employees;                  -- number of characters 
SELECT UPPER(employee_name) FROM employees;                   -- uppercase 
SELECT LOWER(employee_name) FROM employees;                   -- lowercase 
SELECT SUBSTRING(employee_name, 1, 3) FROM employees;         -- first 3 characters 
SELECT REPLACE(email, 'gmail.com', 'company.com') FROM employees; -- replace text 
 
26. Date Functions 
SELECT CURRENT_DATE;                             -- today's date 
SELECT EXTRACT(YEAR FROM joining_date) FROM employees;   -- pull out the year 
Oracle-specific examples: 
SELECT ADD_MONTHS(joining_date, 6) FROM employees;         -- add 6 months 
SELECT MONTHS_BETWEEN(SYSDATE, joining_date) FROM employees; -- months since joining 
Remember: ADD_MONTHS and MONTHS_BETWEEN are Oracle-specific. In 
MySQL, similar results come from DATE_ADD(joining_date, INTERVAL 6 MONTH)

DAY 6 — Grouping Data 
29. GROUP BY 
Why do we need it? Aggregate functions like SUM or AVG normally summarize the whole table. GROUP BY lets 
us get a summary per category — e.g., per department, instead of one number for everyone. 
SELECT department_id, COUNT(*) 
FROM employees 
GROUP BY department_id; 
Shows how many employees are in each department. 
SELECT department_id, AVG(salary) 
FROM employees 
GROUP BY department_id; 
Shows the average salary within each department. 
 
30. HAVING 
SELECT department_id, AVG(salary) 
FROM employees 
GROUP BY department_id 
HAVING AVG(salary) > 70000; 
Only shows departments whose average salary exceeds 70000 — filtering happens after grouping. 
 
31. WHERE vs HAVING (Important!) 
WHERE HAVING 
Filters individual rows Filters groups (after GROUP BY) 
Runs before grouping Runs after grouping 
Cannot use aggregate functions Commonly used with aggregate functions 
 
-- WHERE: filter rows before grouping 
SELECT department_id, AVG(salary) 
FROM employees 
WHERE salary > 50000 
GROUP BY department_id; 
  
-- HAVING: filter groups after grouping 
SELECT department_id, AVG(salary) 
FROM employees 
GROUP BY department_id 
HAVING AVG(salary) > 70000;

DAY 7 — Joins 
32. Why Do We Need Joins? 
Employee data lives in employees, but department names live in departments. If we just query employees, we 
only see department_id (a number), not the department name. JOIN lets us combine rows from two (or more) 
tables based on a matching column, so we can see meaningful, combined results. 
33. INNER JOIN 
SELECT e.employee_name, d.department_name 
FROM employees e 
INNER JOIN departments d 
    ON e.department_id = d.department_id; 
• FROM employees e — start with the employees table, aliased e. 
• INNER JOIN departments d — join with the departments table, aliased d. 
• ON e.department_id = d.department_id — match rows where department IDs are equal. 
 
Output: 
employee_name department_name 
Rahul IT 
Priya IT 
Amit HR 
Sneha Finance 
Raj Sales 
 
INNER JOIN only returns rows that have a match in both tables. 
34. LEFT JOIN 
SELECT e.employee_name, d.department_name 
FROM employees e 
LEFT JOIN departments d 
    ON e.department_id = d.department_id; 
Remember: LEFT JOIN returns all records from the left table (employees) plus matching 
records from the right table (departments). If there's no match, department columns 
show NULL.

Returns all records from the right table (departments) plus matches from the left. In practice, most developers

36. FULL OUTER JOIN 
Conceptually, FULL OUTER JOIN returns all rows from both tables, matched where possible, with NULLs where 
there's no match on either side. 
Remember: MySQL does not directly support FULL OUTER JOIN — alternative approaches (like combining 
LEFT JOIN and RIGHT JOIN with UNION) are needed. We won't go deep into that here. 
37. CROSS JOIN 
SELECT e.employee_name, d.department_name 
FROM employees e 
CROSS JOIN departments d; 
This produces a Cartesian product — every employee paired with every department (5 employees × 4 
departments = 20 rows). Rarely used directly, but important to understand. 
38. SELF JOIN 
A table can be joined with itself — useful for hierarchical data like employee-manager relationships. 
SELECT e.employee_name AS employee, m.employee_name AS manager  
FROM employees e 
LEFT JOIN employees m 
    ON e.manager_id = m.employee_id; 
Here, employees is used twice (as e and m) to compare each employee to their manager, who is also a row in 
the same table. 
39. USING vs ON 
ON lets you compare columns with different names: 
... ON e.department_id = d.department_id 
USING is a shortcut when both tables have a column with the exact same name: 
... JOIN departments USING (department_id)

41. What is a Subquery? 
A subquery is a query inside another query — the inner query runs first, and its result is used by the outer query. 
SELECT employee_name 
FROM employees 
WHERE department_id = ( 
    SELECT department_id FROM departments WHERE department_name = 'IT'  
); 
42. Subquery in WHERE 
Find employees earning more than the average salary: 
SELECT employee_name, salary 
FROM employees 
WHERE salary > ( 
    SELECT AVG(salary) FROM employees 
); 
Step-by-step: First, the inner query SELECT AVG(salary) FROM employees calculates one number — the average 
salary. Then the outer query compares every employee's salary against that number. 
43. Subquery in SELECT 
SELECT employee_name, salary, 
    (SELECT AVG(salary) FROM employees) AS company_avg_salary 
FROM employees; 
Shows each employee's salary next to the overall company average, for easy comparison. 
44. Subquery in FROM 
SELECT department_id, avg_salary 
FROM ( 
    SELECT department_id, AVG(salary) AS avg_salary 
    FROM employees 
    GROUP BY department_id 
) dept_avg 
WHERE avg_salary > 65000; 
The inner query builds a temporary result set (department averages), and the outer query filters that result — 
useful when you need to filter on an already-aggregated value without using HAVING.

Operation Behavior 
UNION Combines results, removes duplicates 
UNION ALL Combines results, keeps duplicates (faster) 
INTERSECT Returns only rows common to both queries 
MINUS / EXCEPT Returns rows in the first query but not the second 
 
Remember: Use UNION ALL when you know there won't be duplicates or don't care about them — it's 
faster since it skips the duplicate-removal step. Oracle uses MINUS; most other databases (including MySQL

DAY 9 — Advanced SQL Basics (Awareness Level) 
48. Indexes 
What is an index? A database index is like the index at the back of a book — instead of scanning every page 
(row) to find something, the database jumps straight to it. 
Why do we need it? Indexes make SELECT queries with WHERE, JOIN, or ORDER BY much faster on large tables. 
CREATE INDEX idx_employee_department 
ON employees(department_id); 
  
DROP INDEX idx_employee_department ON employees;  -- MySQL syntax 
When is it useful? On columns frequently used in WHERE clauses or JOIN conditions, especially in large tables. 
Basic disadvantages: Indexes speed up reads but slow down INSERT/UPDATE/DELETE slightly (since the index 
must also be updated), and they use extra storage. 
 
49. Views 
What is a View? A saved, reusable query that behaves like a virtual table. 
Why use it? Simplifies complex queries, hides sensitive columns, and provides a consistent way to access 
commonly-needed data. 
CREATE VIEW employee_details AS 
SELECT employee_name, salary 
FROM employees; 
  
-- Use it just like a table: 
SELECT * FROM employee_details; 
  
DROP VIEW employee_details; 
View vs Table: A table physically stores data. A view does not store data itself — it just stores a query definition, 
and runs that query fresh each time you use it. 
 
50. Triggers

happens on a table. 
When does it execute? BEFORE or AFTER the triggering event.

51. Stored Procedures 
What is it? A saved block of SQL code (with optional parameters) that you can call repeatedly, instead of 
retyping the same logic. 
Why use it? Reusability, and moving repeated business logic into the database. 
CREATE PROCEDURE GetEmployeesByDept(IN dept_id INT) 
BEGIN 
    SELECT * FROM employees WHERE department_id = dept_id; 
END; 
  
-- Call it: 
CALL GetEmployeesByDept(1); 
 
52. Functions 
What is a database function? Similar to a procedure, but it always returns a single value and can be used 
directly inside a SELECT statement. 
Procedure Function 
Performs an operation Usually returns a value 
Can have OUT parameters Returns a value via RETURN 
Called with CALL Can often be used inside expressions/SELECT 
 
CREATE FUNCTION GetAnnualSalary(monthly_salary DECIMAL(10,2))  
RETURNS DECIMAL(10,2) 
DETERMINISTIC 
BEGIN 
    RETURN monthly_salary * 12; 
END; 
  
SELECT GetAnnualSalary(salary) FROM employees;
